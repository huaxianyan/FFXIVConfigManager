# 角色形象备份格式

## 范围

角色形象数据是配置根目录中的 `FFXIV_CHARA_01.dat`～`FFXIV_CHARA_40.dat`。它不属于账号或 `FFXIV_CHR...` 角色目录，文件名中的数字只表示当前游戏栏位。

备份与栏位解耦：备份记录保留原始文件名用于溯源，但备份列表不把源栏位作为名称或身份。恢复时由用户选择目标配置源和 `01～40` 中的目标栏位。

## 存储位置

每份角色形象使用独立 ZIP：

```text
<备份位置>/appearance-backups/<年份>/<月份>/
  <UTC 时间>_<备份 ID>.ffxivappearance.zip
```

归档固定包含：

```text
manifest.json
appearance.dat
```

`appearance.dat` 是游戏原文件的逐字节副本。应用不会根据 Manifest 重新生成角色形象数据。

## Manifest

当前 `formatVersion` 为 `1`。Manifest 包含：

- 备份 ID 和创建时间
- 手动备份或覆盖前恢复点原因
- 原始文件名
- 原文件大小和 SHA-256
- 用于识别与筛选的种族、部族、性别、备注、DAT 格式版本和游戏保存时间

中文种族和性别名称不写入 Manifest，由界面根据数字枚举生成。

## 校验

读取备份时必须同时验证：

1. ZIP 只能包含两个固定条目。
2. Manifest 结构和版本有效。
3. `appearance.dat` 固定为 212 字节。
4. SHA-256 与 Manifest 一致。
5. DAT Magic 为 `0x2013FF14`。
6. DAT 内部校验和正确。
7. 从 DAT 重新解析的识别信息与 Manifest 一致。

备注从 DAT 的 `0x30` 开始，按 NUL 终止的 UTF-8 文本读取。备注原文不写入诊断日志。

## 恢复与回滚

恢复目标始终由用户选择，源文件名不决定目标栏位。

目标栏位已有数据时：

1. 界面展示现有数据的种族、性别和备注。
2. 用户需要二次确认覆盖。
3. 将现有数据保存为独立的「覆盖前恢复点」。
4. 在目标配置源中暂存新文件和回滚副本。
5. 写入事务日志后替换目标文件。
6. 进行写后 SHA-256 校验。
7. 失败或取消时恢复原文件。

扫描配置源时会先处理遗留的角色形象恢复事务。FFXIV 或 XIVLauncher 的进程状态不会阻止备份和恢复。
