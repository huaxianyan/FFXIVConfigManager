# Windows 手动验收计划（0.1.0）

自动化测试不会写入真实 FFXIV 配置，首次手动验收建议使用独立沙盒目录，确认行为后再测试实际配置目录。

## 1. 创建沙盒

选择两个已有角色配置目录作为数据来源，执行：

```powershell
./scripts/create-test-sandbox.ps1 `
  -SourceCharacterPath "C:\...\FFXIV_CHR..." `
  -TargetCharacterPath "C:\...\FFXIV_CHR..."
```

脚本只读取源目录，并在以下位置创建副本：

```text
%TEMP%\FFXIVConfigManager-ManualTest
```

沙盒角色 ID：

```text
FFXIV_CHR1111111111111111
FFXIV_CHR2222222222222222
```

## 2. 启动便携版

解压并运行：

```text
artifacts/FFXIVConfigManager-win-x64.zip
```

验收：

- 程序图标和窗口正常。
- Windows 默认国际服目录被自动发现。
- 同时启动第二个实例时，第二个实例立即退出。
- 界面在 100%、125%、150% DPI 下没有控件重叠或无法滚动。

## 3. 添加沙盒配置源

- 名称填写「手动测试」。
- 类型选择「其他」。
- 添加 `%TEMP%\FFXIVConfigManager-ManualTest`。
- 确认两个沙盒角色均出现。
- 分别保存角色标记。
- 关闭并重新打开应用，确认配置源和角色标记仍然存在。

## 4. 备份

- 将备份库设置为新的空目录。
- 为目标沙盒角色创建备份。
- 确认角色管理页面显示该角色的备份数量、有效数量、损坏数量和最近备份时间。
- 确认备份页面以角色为单位显示，不直接展开同一角色的多份备份。
- 点击角色管理页面的「恢复备份」或备份页面的「管理备份」，确认打开同一个次级窗口。
- 在次级窗口选择一份备份，确认预览前不能执行恢复，预览后可以恢复或删除。
- 确认次级窗口只使用标题栏关闭按钮，窗口内容中没有单独的「关闭」按钮。
- 使用普通 ZIP 工具打开，确认存在 `manifest.json` 和 `files/`，且已设置角色标记时 `source.characterAlias` 正确。
- 将一个已备份角色目录临时移出配置源并重新扫描，确认备份历史仍显示 Manifest 中的角色标记；选择本地配置源并预览、恢复后，确认以原始 `FFXIV_CHR...` 名称重建角色目录。
- 点击预览，确认逐文件显示「相同」。
- 复制备份后修改 ZIP 内一个文件，把修改后的副本放回备份目录。
- 重新扫描，确认修改后的备份显示「损坏」，且不影响其他备份。

## 5. 沙盒迁移

- 在迁移区域选择两个不同的沙盒角色。
- 保持默认安全范围。
- 生成预览，确认列出相同、不同或缺失文件。
- 点击「确认迁移」。
- 确认操作成功，备份历史新增：
  - `BeforeMigration` 目标恢复点。
  - `MigrationSource` 源配置备份。
- 重新生成迁移预览，已迁移文件应显示相同。

## 6. 沙盒恢复

- 找到迁移前的目标恢复点。
- 点击预览。
- 点击「确认恢复到原角色」。
- 确认恢复成功。
- 确认恢复前又生成一个 `BeforeRestore` 恢复点。
- 重新预览迁移源备份，应再次看到迁移差异。

## 7. 游戏运行期间

在 FFXIV 运行时重复沙盒备份和迁移：

- 应用不得因为检测到进程而禁用操作。
- 沙盒文件不受游戏写入，操作应正常完成。
- 再根据需要在角色选择界面对实际角色执行一次「创建备份」。
- 如果文件读取期间发生变化，应重试或给出稳定性错误，而不是生成半成品备份。

## 8. 软件设置备份

- 在配置与存储页面确认软件设置备份初始状态正确。
- 选择角色管理和自定义配置源范围创建软件设置备份。
- 确认备份写入 `<备份位置>/settings/settings.ffxivconfig-settings.json`。
- 修改一个角色标记，只恢复自定义配置源，确认角色标记保持不变。
- 只恢复角色管理范围，确认角色标记恢复，当前备份位置保持不变。
- 再次创建软件设置备份，确认旧文件被原子覆盖且没有产生历史版本。
- 损坏设置备份文件后重新扫描，确认界面显示损坏状态并禁止恢复。

## 9. 自动更新

需要存在高于测试程序版本的正式 GitHub Release：

- 把旧版本分别解压到普通目录、含空格的深层目录，确认启动后能够发现新版本。
- 点击「下载并安装」，确认下载期间界面显示忙碌状态。
- 确认程序自动关闭、原位置的 EXE 被替换并自动重启，新版本号正确。
- 确认角色标记、自定义配置源和备份位置保持不变。
- 确认安装目录中没有 `.update` 或 `.update-backup` 残留文件。
- 临时移除安装目录写权限，确认程序在关闭前报告失败且旧版本仍可运行。
- 使用错误的 `.sha256` 或损坏 ZIP 测试源，确认程序拒绝安装且旧版本文件不变。
- 在替换提交阶段注入失败，确认恢复副本自动回滚。

## 10. 诊断信息

如果发生异常，保留：

```text
%LOCALAPPDATA%\FFXIVConfigManager\settings.json
%LOCALAPPDATA%\FFXIVConfigManager\logs\
%LOCALAPPDATA%\FFXIVConfigManager\updates\
%TEMP%\FFXIVConfigManager-update-error.log
```

同时记录：

- 操作步骤。
- 界面提示。
- 是否运行 FFXIV。
- 出错的备份文件名。
- DPI 和 Windows 缩放比例。

不要将真实角色 DAT 文件、聊天日志或包含个人路径的设置文件提交至公开 Issue。
