# Windows 手动验收计划（当前测试版）

自动化测试不会写入真实 FFXIV 配置，首次手动验收建议使用独立沙盒目录，确认行为后再测试实际配置目录。

## 1. 创建沙盒

选择两个已有角色配置目录作为数据来源，执行：

```powershell
./scripts/create-test-sandbox.ps1 `
  -SourceCharacterPath "C:\...\FFXIV_CHR..." `
  -TargetCharacterPath "C:\...\FFXIV_CHR..."
```

脚本只读取源目录，并在以下位置创建副本：

```text
%TEMP%\FFXIVConfigManager-ManualTest
```

沙盒角色 ID：

```text
FFXIV_CHR1111111111111111
FFXIV_CHR2222222222222222
```

## 2. 启动便携版

解压并运行：

```text
artifacts/FFXIVConfigManager-win-x64.zip
```

验收：

- 程序图标和窗口正常。
- Windows 默认国际服目录被自动发现。
- 同时启动第二个实例时，第二个实例立即退出。
- 界面在 100%、125%、150% DPI 下没有控件重叠或无法滚动。

## 3. 添加沙盒配置源

- 名称填写「手动测试」。
- 类型选择「其他」。
- 添加 `%TEMP%\FFXIVConfigManager-ManualTest`。
- 确认两个沙盒角色均出现。
- 分别保存角色标记。
- 启用「只显示有角色标记」，确认未标记角色从角色管理列表隐藏，但概览角色总数和迁移候选不变。
- 关闭并重新打开应用，确认配置源、角色标记和角色筛选状态仍然存在。
- 清除一个当前可见角色的标记并保存，确认启用筛选时该角色立即从列表隐藏。

## 4. 备份

- 将备份库设置为新的空目录。
- 为目标沙盒角色创建备份。
- 确认角色管理页面显示该角色的备份数量、有效数量、损坏数量和最近备份时间。
- 确认备份页面以角色为单位显示，不直接展开同一角色的多份备份。
- 点击角色管理页面的「恢复备份」或备份页面的「管理备份」，确认打开同一个次级窗口。
- 在次级窗口选择一份备份，确认预览前不能执行恢复，预览后可以恢复或删除。
- 第一次点击删除后切换到另一份备份，确认删除按钮恢复为普通状态，上方删除确认提示同步清除并显示新选择的正常状态。
- 确认次级窗口只使用标题栏关闭按钮，窗口内容中没有单独的「关闭」按钮。
- 使用普通 ZIP 工具打开，确认存在 `manifest.json` 和 `files/`，且已设置角色标记时 `source.characterAlias` 正确。
- 将一个已备份角色目录临时移出配置源并重新扫描，确认备份历史仍显示 Manifest 中的角色标记；选择本地配置源并预览、恢复后，确认以原始 `FFXIV_CHR...` 名称重建角色目录。
- 点击预览，确认逐文件显示「相同」。
- 复制备份后修改 ZIP 内一个文件，把修改后的副本放回备份目录。
- 重新扫描，确认修改后的备份显示「损坏」，且不影响其他备份。

## 5. 沙盒迁移

- 在迁移区域选择两个不同的沙盒角色。
- 保持默认安全范围，确认范围说明明确列出 `UISAVE.DAT` 中的肖像数据和 `GEARSET.DAT` 中的即时肖像关联，并提示这两个复合文件会整体迁移。
- 生成预览，确认列出相同、不同或缺失文件；源角色存在这两个文件时，预览应同时包含 `UISAVE.DAT` 和 `GEARSET.DAT`。
- 生成预览后切换来源角色、目标角色或迁移范围，确认预览立即失效、「确认迁移」被禁用，顶部状态不再显示预览就绪。
- 点击「确认迁移」。
- 确认操作成功，备份历史新增：
  - `BeforeMigration` 目标恢复点。
  - `MigrationSource` 源配置备份。
- 重新生成迁移预览，已迁移文件应显示相同。

## 6. 沙盒恢复

- 找到迁移前的目标恢复点。
- 点击预览。
- 点击「确认恢复到原角色」。
- 确认恢复成功。
- 确认恢复前又生成一个 `BeforeRestore` 恢复点。
- 重新预览迁移源备份，应再次看到迁移差异。

## 7. 游戏运行期间

在 FFXIV 运行时重复沙盒备份和迁移：

- 应用不得因为检测到进程而禁用操作。
- 沙盒文件不受游戏写入，操作应正常完成。
- 再根据需要在角色选择界面对实际角色执行一次「创建备份」。
- 如果文件读取期间发生变化，应重试或给出稳定性错误，而不是生成半成品备份。

## 8. 软件设置备份

- 在「配置」页面确认卡片从上到下依次为「软件更新」「软件设置备份」「配置源」「备份存储」，并确认软件设置备份初始状态正确。
- 选择角色管理和自定义配置源范围创建软件设置备份。
- 确认备份写入 `<备份位置>/settings/settings.ffxivconfig-settings.json`。
- 修改一个角色标记，只恢复自定义配置源，确认角色标记保持不变。
- 只恢复角色管理范围，确认角色标记恢复，当前备份位置保持不变。
- 再次创建软件设置备份，确认旧文件被原子覆盖且没有产生历史版本。
- 损坏设置备份文件后重新扫描，确认界面显示损坏状态并禁止恢复。

## 9. 角色形象备份与恢复

建议先复制有效的 `FFXIV_CHARA_*.dat` 到独立配置源目录进行测试：

- 打开「角色形象」，确认界面为左右列表；左栏只能选择游戏配置源，右栏默认是「备份」，并可切换为任意游戏配置源。
- 确认游戏配置源列表显示 `01～40` 全部栏位，空栏位明确显示为可写入目标，非空栏位显示正确的种族、性别和备注。
- 左栏选择非空栏位、右栏保持「备份」，确认执行备份后备份列表显示识别信息，但不显示原来所在的栏位。
- 分别选择种族和性别筛选，确认可以单独筛选和组合筛选。
- 输入备注的一部分，确认搜索可以单独使用，也可以与种族、性别筛选组合使用。
- 关闭并重新打开应用，确认备份列表可以完全从 ZIP 和 Manifest 重建。
- 保持左右数据源不变并切换方向，选择右栏备份和左栏空栏位，确认可以恢复且生成正确的 `FFXIV_CHARA_XX.dat`。
- 选择已有数据的目标栏位，确认第一次点击只显示覆盖警告；切换备份、目标栏位、配置源或操作方向后，按钮和顶部覆盖警告同步复位。
- 第一次点击删除后切换到另一份形象备份或修改筛选、搜索条件，确认删除按钮和顶部删除警告同时复位。
- 右栏切换为不同配置源，确认左右配置源之间可以迁移；方向切换后迁移方向反转且已有选择不丢失。
- 迁移时确认来源形象自动保存为备份；覆盖已有目标时，目标原数据另存为「覆盖前恢复点」。
- 左右选择同一个配置源时，确认迁移按钮禁用。
- 再次点击确认覆盖，确认操作成功。
- 在替换后注入失败，确认目标栏位恢复为原数据。
- 修改归档中的 `appearance.dat` 或 Manifest，确认备份显示损坏且不能恢复。
- 在 FFXIV 运行期间重复备份和恢复，确认不会因进程状态而禁止操作。

## 10. 肖像管理

必须只对沙盒角色执行写入测试：

- 打开一级「肖像管理」，确认左右栏均可独立选择角色或「备份」。
- 选择角色后，确认列表按真实套装编号升序排列，编号允许不连续；每项只显示编号、职业图标、UTF-8 原始套装名称和肖像最后更新时间。
- 左栏选择角色、右栏选择「备份」；未选择左栏具体肖像时不能备份。
- 选中一条肖像但不填写方案名称或备注时仍不能备份；两项都填写后创建备份。
- 确认新方案只包含选中的一条肖像；ZIP 必须且只能包含 `manifest.json` 和 118 字节的 `portrait.dat`。
- 确认备份列表只显示方案名称、备注和备份时间，不显示来源套装编号、职业图标或套装名称；这些来源信息仍保留在 Manifest 中。
- 分别输入方案名称和备注中的一部分，确认搜索结果正确；清空搜索后恢复完整列表。
- 选中有效方案后，确认卡片右上角显示编辑图标，完整性状态位于右下角；未选中方案和损坏方案不提供可用的编辑入口。
- 点击编辑图标，确认小窗口显示当前方案名称和备注；修改后保存，确认列表立即更新，`portrait.dat`、备份 ID、创建时间、来源信息和数据哈希保持不变。
- 清空名称或备注，确认不能保存；使用窗口标题栏的关闭按钮退出，确认原方案保持不变。
- 在编辑窗口打开后从外部修改方案归档，确认应用拒绝覆盖外部修改并要求刷新。
- 修改方案使其不再符合当前搜索条件，确认列表移除该项并显示明确的保存成功提示。
- 选中方案后点击「删除方案」，确认第一次点击只显示警告，第二次点击「确认删除」才永久删除归档；未选中方案时删除按钮不可用。
- 显示删除确认后切换方案、修改搜索条件、切换数据源或切换操作方向，确认删除按钮恢复为普通状态，上方删除确认提示同步清除。
- 保持左栏角色、右栏「备份」不变，点击中间的方向切换按钮；确认左右栏选择不丢失，栏标题与箭头反向，操作从「备份」切换为「恢复」，再次切换后恢复为「备份」。
- 执行恢复时，必须同时选中来源备份方案和目标角色的具体套装肖像，第一次点击只显示覆盖确认，第二次点击才恢复。
- 左右栏选择两个不同角色；必须同时选中来源和目标具体肖像，操作名称显示为「迁移」；切换方向后迁移方向反转但角色和肖像选择不丢失，并要求二次确认。
- 确认恢复或迁移前自动新增目标肖像恢复点，操作后目标的套装编号、套装名称和 Banner 关联不变。
- 确认目标 `GEARSET.DAT` 字节不变，`UISAVE.DAT` 中除选中 BANNER 记录外的字节不变。
- 左右栏选择同一角色、同一个「备份」或两栏都选择「备份」，确认操作按钮禁用。
- 在扫描后修改来源或目标副本，确认应用拒绝使用过期选择并要求刷新。
- 修改归档中的 `portrait.dat` 或 Manifest，确认该方案显示损坏且不能恢复。
- 在目标替换后注入失败，确认完整 `UISAVE.DAT` 回滚，事务目录被清理。
- FFXIV 运行期间不应因进程状态禁止操作；若文件持续变化，应报告稳定性错误。
- 测试结束后删除沙盒、肖像测试备份和事务残留，并重新确认真实来源文件的 SHA-256、大小和修改时间未变化。

## 11. 自动更新

需要存在高于测试程序版本的正式 GitHub Release：

- 把旧版本分别解压到普通目录、含空格的深层目录，确认启动后能够发现新版本。
- 点击「下载并安装」，确认下载期间界面显示忙碌状态。
- 确认程序自动关闭、原位置的 EXE 被替换并自动重启，新版本号正确。
- 确认角色标记、自定义配置源和备份位置保持不变。
- 确认安装目录中没有 `.update` 或 `.update-backup` 残留文件。
- 临时移除安装目录写权限，确认程序在关闭前报告失败且旧版本仍可运行。
- 使用错误的 `.sha256` 或损坏 ZIP 测试源，确认程序拒绝安装且旧版本文件不变。
- 在替换提交阶段注入失败，确认恢复副本自动回滚。

## 12. 诊断信息

如果发生异常，保留：

```text
%LOCALAPPDATA%\FFXIVConfigManager\settings.json
%LOCALAPPDATA%\FFXIVConfigManager\logs\
%LOCALAPPDATA%\FFXIVConfigManager\updates\
%TEMP%\FFXIVConfigManager-update-error.log
```

同时记录：

- 操作步骤。
- 界面提示。
- 是否运行 FFXIV。
- 出错的备份文件名。
- DPI 和 Windows 缩放比例。

不要将真实角色 DAT 文件、聊天日志或包含个人路径的设置文件提交至公开 Issue。
