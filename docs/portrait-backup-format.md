# 角色肖像备份格式

本文中的「角色肖像」是套装绑定的即时肖像，不是 `FFXIV_CHARA_01.dat`～`FFXIV_CHARA_40.dat` 角色形象预设。

## 存放位置与文件名

肖像备份保存在：

```text
<备份位置>/portrait-backups/<年份>/<月份>/
```

每个归档只保存一条用户明确选择的肖像，扩展名为：

```text
.ffxivportrait.zip
```

文件名由 UTC 创建时间和随机 `BackupId` 组成，不使用角色名、套装名或备注，避免非法路径字符和同名覆盖。

## 归档结构

归档必须且只能包含：

```text
manifest.json
portrait.dat
```

- `manifest.json`：版本化元数据、来源套装信息和完整性信息。
- `portrait.dat`：从 `UISAVE.DAT` 的 `BANNER` 分段提取的 118 字节原始肖像记录。

读取时会限制条目数量和大小，并拒绝缺失、额外或损坏的内容。`portrait.dat` 的 SHA-256 必须与 Manifest 一致，而且记录字段标记必须通过严格解析。

## Manifest v1

主要字段如下：

| 字段 | 含义 |
| --- | --- |
| `formatVersion` | 当前固定为 `1` |
| `backupId` | 备份方案的独立 UUID |
| `createdAtUtc` | 创建时间 |
| `reason` | `Manual` 或 `BeforeTransfer` |
| `schemeName` | 用户填写的备份方案名称，必填，最长 100 个字符 |
| `note` | 用户填写的备注，必填，最长 500 个字符 |
| `source.characterFolder` | 来源角色目录名，仅用于溯源 |
| `source.gearsetNumber` | 来源游戏套装编号，范围 `1～100` |
| `source.classJobId` | 来源职业 ID，用于显示职业图标 |
| `source.gearsetName` | 来源套装 UTF-8 原始名称 |
| `dataSize` | 固定为 `118` |
| `sha256` | `portrait.dat` 的 SHA-256 |
| `portraitLastUpdatedUtc` | 肖像记录保存的最后更新时间 |

方案名称和备注在手动备份时都不能为空。自动创建的操作前恢复点也使用同一格式，但 `reason` 为 `BeforeTransfer`，名称和备注由应用明确标注。

备份列表只展示方案名称、备注、备份时间和完整性，并支持按方案名称或备注搜索。来源套装编号、职业和名称继续保存在 Manifest 中用于校验与溯源，但不在列表中展示，避免让人误以为恢复时会覆盖目标套装信息。

选中有效方案后，可以通过卡片右上角的编辑按钮修改方案名称和备注。编辑不会修改 `backupId`、创建时间、备份原因、来源信息、肖像更新时间、数据哈希或 `portrait.dat`。应用会重新校验原归档，将修改后的 Manifest 和原始肖像数据写入临时 ZIP，完整校验后使用带回滚副本的原子替换提交；如果归档在编辑期间发生变化，或者写入、校验、替换失败，则拒绝保存或恢复原归档。选中的方案也可以通过二次确认永久删除。

## 恢复与迁移语义

备份与源栏位、源 Banner 索引解耦。恢复时必须明确选择目标角色中的具体套装肖像。

应用不会把整条来源记录直接覆盖目标记录，而是：

1. 重新校验来源备份，或确认来源角色肖像自界面扫描后没有变化；
2. 重新扫描并确认目标套装及其 Banner 关联没有变化；
3. 自动备份目标肖像作为操作前恢复点；
4. 只复制已验证的画面参数，保留目标记录 ID、角色数据、装备校验和及关联状态；
5. 更新肖像最后更新时间；
6. 仅替换 `UISAVE.DAT` 中目标 BANNER 记录，其他分段和未知字节保持原样；
7. 使用暂存文件、事务日志、写后 SHA-256、重新解析和失败回滚完成提交。

当前操作不修改 `GEARSET.DAT`，因为目标是用户明确选择的、已经绑定肖像的套装。应用不创建新套装、不创建新 Banner 记录，也不改变套装与 Banner 的关联。

## 兼容性边界

v1 格式保存游戏原始记录，因此不会通过解析字段重新生成肖像。但恢复写入只支持当前已严格验证的 118 字节记录布局和字段标记顺序。遇到未知版本、长度、非法 UTF-8 套装名、关联越界或字段标记变化时，应用会拒绝操作，而不是猜测格式。
