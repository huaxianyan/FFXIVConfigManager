# 自动更新

自动更新首期支持 Windows 单文件发布版。程序启动后会读取 GitHub 仓库的最新正式 Release，也可以在「设置」页面手动检查。

## 更新来源

更新服务只接受最新 Release 中名称固定的两个资产：

```text
FFXIVConfigManager-win-x64.zip
FFXIVConfigManager-win-x64.zip.sha256
```

程序下载 SHA-256 校验文件和 ZIP，下载期间显示已下载大小、总大小和百分比；服务器未提供文件总大小时，改为显示已下载大小和循环进度动画。程序会流式计算 ZIP 的实际 SHA-256，并在一致后解压。ZIP 只允许包含根目录下的 `FFXIVConfigManager.exe`、`LICENSE`、`README.md` 和 `LEGAL.md`，其中应用程序必须存在，其他 3 个文档可以省略。出现目录、重复条目、未知文件、空文件或超出大小限制的文件时会拒绝更新。下载包、解压后程序和写入安装目录后的临时程序都会重新校验。

自动更新只从归档中提取经过验证的应用程序文件，用于自替换。许可证和说明文档随完整便携包分发，更新现有目录时不会覆盖用户自行保留的文档。

## 任意安装位置

目标位置不从注册表、快捷方式或固定安装目录推断，而是使用当前运行的 `FFXIVConfigManager.exe` 路径。因此，只要用户对目录有写权限，软件解压到任意本地目录后都可以原地更新。自动更新不会请求管理员权限；位于受保护目录且当前用户不可写时，会在关闭程序前报告失败。

开发构建包含相邻 DLL，不允许自动替换本体，但仍可检查更新。

## 自替换事务

Windows 不允许运行中的 EXE 覆盖自身。更新过程使用下载到本地应用数据目录的新版本单文件 EXE 作为临时更新器：

1. 主程序下载、解压并完整校验新版本。
2. 主程序确认当前安装目录可写，生成更新计划并启动临时更新器。
3. 主程序退出，释放正在运行的 EXE。
4. 更新器把新 EXE 复制到安装目录内的临时文件并再次校验。
5. 更新器将旧 EXE 原子改名为恢复副本，再将临时文件原子改名为正式 EXE。
6. 更新器校验正式 EXE 并启动新版本。
7. 新版本持续运行后，更新器删除恢复副本；新版本在更新器退出后清理下载目录。

提交阶段发生任何异常时，更新器会删除未完成的新文件并将恢复副本改回原文件。若更新后的程序在启动确认期内退出，也会回滚并重新启动旧版本。更新故障会记录到更新暂存目录的 `update.log`，无法使用该目录时回退到系统临时目录中的 `FFXIVConfigManager-update-error.log`。

## 边界

- 当前只支持 GitHub 正式 Release，不自动安装草稿或预发布版本。
- 当前只支持稳定的三段版本号，如 `v0.2.0`。
- 更新过程不会修改 `%LOCALAPPDATA%/FFXIVConfigManager` 中的用户设置、日志和备份位置。
- Linux 和 macOS 尚未实现自动替换，只保留后续平台实现空间。
