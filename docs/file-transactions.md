# 文件恢复事务

恢复和角色迁移共用同一个文件事务引擎，不依赖 FFXIV 进程状态。

## 正常流程

1. 对来源快照重新执行 Manifest、大小和 SHA-256 校验；
2. 创建目标角色操作前恢复点；
3. 将快照内声明的文件解压至目标磁盘上的事务暂存目录；
4. 对暂存文件重新执行大小和 SHA-256 校验；
5. 稳定读取所有现有目标文件并创建本地回滚副本；
6. 持久化事务日志；
7. 逐文件替换目标；
8. 每次替换后立即稳定读取并校验 SHA-256；
9. 完成后删除事务暂存数据，保留版本化恢复点。

## 失败与取消

任意文件失败或用户取消时，事务引擎按相反顺序恢复已经提交的文件：

- 原来存在的文件从本地回滚副本恢复，并验证原始 SHA-256；
- 原来不存在的文件会被删除；
- 未提交的文件不会写入目标；
- 回滚完成后删除事务目录；
- 回滚不完整时保留事务日志和回滚副本，并向 UI 报告严重错误。

## 进程意外终止

事务数据位于角色目录下：

```text
FFXIV_CHR.../.ffxivconfigmanager/transactions/<operation-id>/
```

应用启动扫描角色时会检查这些目录。对于提交过程中意外中断的事务，应用会根据持久化日志自动回滚；损坏或不可信的事务日志不会被执行，并会显示诊断错误。

## 并发修改

FFXIV 运行状态不会阻止操作。安全边界建立在文件事实上：

- 读取前后比较大小和修改时间；
- 读取期间变化会重试；
- 写入后计算稳定 SHA-256；
- 无法获得稳定文件时终止并回滚；
- 不结束、注入或控制游戏进程。
